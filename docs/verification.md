## 验收方法

项目除单元测试外，还使用多层冒烟流程验证：

1. 服务健康与核心 API；
2. MCP 只读调用；
3. 专业部门打包产物；
4. 专业工具 Web 工作区；
5. macOS 桌面应用启动及服务恢复；
6. 真实用户流程的手工回归。

真实账户相关验收执行账户读取与 MT5 `OrderCheck` 安全预检，不写入交易记录，也未发送真实订单。交易执行代码通过模拟网关、订单指纹、授权过期、授权复用和参数篡改等自动化场景验收。

## 已处理的典型缺陷

- 不同对话入口携带的上下文不一致，造成回答详略差异；
- 数据时间字段缺失时被错误判定为真实的零持仓；
- 旧进程未退出导致桌面应用加载旧前端；
- 隔天启动仍展示前一天对话和报告；
- 同一风险事项每天重复生成卡片；
- 专业工具页面和助理对话之间缺少返回与上下文衔接；
- MT5 命令邮箱扩展名不被终端文件沙箱接受，以及 `OrderCheck` 成功返回码判断错误。
